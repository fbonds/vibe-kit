## What the owner has and has not approved about the evaluation

The owner did not approve the outline. They decided on the fork instead, and later approved
copying the finished draft into vibe-kit. **The owner has not said they have read the
evaluation or that they accept its findings or its path.** Treat it as the session's
analysis, awaiting the owner's review, and not as a plan the owner has agreed to.

Its findings, in brief. Strengths that none of the eight others match: a report shape for
every check that includes what was broken to show it can fail and what was not checked;
committed, pushed and released as three questions; dated facts with the commands that
re-check them; decisions replaced rather than rewritten; no install. Gaps, most important
first:

1. It covers keeping state and checking work, and has no method for building: no route from
   idea to specification, plan and tasks, and no testing approach.
2. Almost all of it is prose Claude may decide does not apply. Anthropic's best-practices
   page says things that must happen every time belong in hooks, deny rules or managed
   settings.
3. Its examples come from one project's release engineering, which this reader may not
   recognise.
4. Rule 10 asks the owner to approve diffs, while project-kit's README promises an audit
   "without reading a line of code".
5. No measured evidence. None of the eight others has any either.
6. No size limit on the state file. project-kit's own `NEXT.md` was 4,758 words.
7. Claude Code features such as plan mode, checkpoints and sandboxing are unused.

Its proposed path, not approved: measure first, add a light build loop, move the rules that
must always hold into hooks and settings, rewrite the examples for this reader, change what
the owner approves to proposals and observed behaviour, and set a size budget for the state
file.

## Lessons from this session that belong in vibe-kit's Traps

Each happened in this session.

- **A comparison claim was too strong.** The outline said none of the other methods had
  anything like the kit's verification shape. Spec Kit requires unit tests "confirmed to
  FAIL (Red phase)", and Anthropic asks for "evidence". It was corrected before writing.
  Recognise it: "none of the others" before each one has been checked.
- **A quote was credited to the wrong page.** The draft put "Claude is allowed to decide a
  guideline doesn't apply" on Anthropic's memory page. It is on the best-practices page. It
  was caught by grepping the saved pages for each quote.
- **A file's contents were described from a guess.** `docs/README.md` first described the
  `.raw` and `.txt` source files before either was opened. It was corrected after reading
  them.
- **An edit inside a wrapped paragraph left a short line,** in project-kit's `NEXT.md`, in
  `32084f3`, fixed in `83b8a27`. project-kit's width check finds long lines only, so it
  missed a short one. The file was read back after the commit instead of before it.
- **A snapshot of unpushed commits goes stale with each commit that corrects it.** Write the
  command that answers the question, not only the snapshot.
- **A stated size was wrong.** The source pages were described as about 1 MB. They are
  2.5 MB, measured with `du` after copying.
