# Test of kit/ in a real Claude Code session, 2026-11-23 to 2026-11-24

The first time `kit/` ran inside Claude Code. The owner ran the session; the building
session read its record from `~/.claude/projects/` and inspected the test folders.

## Setup

`kit/` at commit `6bea07b` was copied into an empty folder, `~/code/vibe-kit-test`, made a
git repository with no commits. A second folder, `~/code/vibe-kit-test-remote.git`, stood
in for an online backup, so nothing left the computer. Claude Code v2.1.331, in auto mode.
The owner's global instructions loaded too, so every reply mixes the kit with them: the
folder check and the folder path at the end of each reply came from the owner's file, not
the kit.

## Results

**SessionStart hook at startup: works.** The record has `SessionStart:startup`,
`hook_success`, carrying `PROGRESS.md` and the git status, and the same text reached the
model.

**SessionStart hook after compaction: works.** After `/compact`, the record has
`SessionStart:compact`, `hook_success`, carrying the current `PROGRESS.md` and
`## main...origin/main [ahead 1]`.

**SessionStart hook on resume: not known.** After `claude --continue`, the record has no
resume entry. Claude checked the state itself and reported it correctly.

**Claude speaking first: impossible.** Claude said nothing until the owner typed. The
design assumed Claude would open the session.

**The opening: worked as written, then replaced.** Claude's first reply listed what works,
what is in progress, what is next, and saved, backed up online and live, in plain words.
The owner judged it the wrong opening for this reader: "they want to drive a nail, vibe kit
is the hammer." It was replaced on 2026-11-24.

**Saving: works.** One commit, three files, a plain message. Nothing pushed.

**Facts checked before they are written down: failed.** Claude wrote "Backed up online:
not set up. No online location is connected (checked 2026-11-23)" when a backup location
had been connected before that write. It reused an earlier check. Believing no location
existed, it then proposed creating a repository on the owner's GitHub account. It asked
first, and the owner stopped it. Once told, it checked, found the local folder, and
explained in plain words that a local copy is not an online backup.

**Ask before push: works.** Claude Code showed a permission prompt before
`git push -u origin main`, which ran inside a compound command. The owner approved it, and
the push succeeded. The prompt does not appear in the session record. Claude Code's
permission-modes documentation, read on 2026-11-24 through a summarising fetch, says ask
rules that match a command's content "fall back to a permission prompt" in auto mode, so
the prompt came from the ask rule.

**Force push denied: works.** "1 action not run · permission denied · rule from shared
project settings". The backup folder was unchanged.

**Edits shown to the reader as diffs: a problem, then fixed by a setting.** Claude Code
displays every file edit with its added and removed lines. Claude does not choose this,
and `CLAUDE.md` cannot turn it off. A follow-up on 2026-11-24 added `"viewMode": "focus"`
to the test project's settings. With the fullscreen renderer, which the owner's session
already used, an edit then showed as one line, "Edited 1 file +3 -2", with no changed
lines, and no separate diff panel opened. The classic renderer was not tried.

## Not tested

The `-f` push form, `git reset --hard`, `git clean`, the staging denies, and the `.env`
read denies. A session without the owner's global instructions. A reader who is not the
owner.

## Lessons

- A session record does not show every permission prompt. Ask what the screen showed.
- A test run by the kit's author carries the author's own instructions. A clean test needs
  a session without them.
