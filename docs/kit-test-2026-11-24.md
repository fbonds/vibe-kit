# Test of kit/ in a real Claude Code session, 2026-11-23 to 2026-11-24

The first time `kit/` ran inside Claude Code. The owner ran the session; the building
session read its record from `~/.claude/projects/` and inspected the test folders.

## Setup

`kit/` at commit `6bea07b` was copied into an empty folder, `~/code/vibe-kit-test`, made a
git repository with no commits. A second folder, `~/code/vibe-kit-test-remote.git`, stood
in for an online backup, so nothing left the computer. Claude Code v2.1.331, in auto mode.
The owner's global instructions loaded too, so every reply mixes the kit with them: the
folder check and the folder path at the end of each reply came from the owner's file, not
the kit.

## Results

**SessionStart hook at startup: works.** The record has `SessionStart:startup`,
`hook_success`, carrying `PROGRESS.md` and the git status, and the same text reached the
model.

**SessionStart hook after compaction: works.** After `/compact`, the record has
`SessionStart:compact`, `hook_success`, carrying the current `PROGRESS.md` and
`## main...origin/main [ahead 1]`.

**SessionStart hook on resume: not known.** After `claude --continue`, the record has no
resume entry. Claude checked the state itself and reported it correctly.

**Claude speaking first: impossible.** Claude said nothing until the owner typed. The
design assumed Claude would open the session.

**The opening: worked as written, then replaced.** Claude's first reply listed what works,
what is in progress, what is next, and saved, backed up online and live, in plain words.
The owner judged it the wrong opening for this reader: "they want to drive a nail, vibe kit
is the hammer." It was replaced on 2026-11-24.

**Saving: works.** One commit, three files, a plain message. Nothing pushed.

**Facts checked before they are written down: failed.** Claude wrote "Backed up online:
not set up. No online location is connected (checked 2026-11-23)" when a backup location
had been connected before that write. It reused an earlier check. Believing no location
existed, it then proposed creating a repository on the owner's GitHub account. It asked
first, and the owner stopped it. Once told, it checked, found the local folder, and
explained in plain words that a local copy is not an online backup.

**Ask before push: works.** Claude Code showed a permission prompt before
`git push -u origin main`, which ran inside a compound command. The owner approved it, and
the push succeeded. The prompt does not appear in the session record. Claude Code's
permission-modes documentation, read on 2026-11-24 through a summarising fetch, says ask
rules that match a command's content "fall back to a permission prompt" in auto mode, so
the prompt came from the ask rule.

**Force push denied: works.** "1 action not run · permission denied · rule from shared
project settings". The backup folder was unchanged.

**Edits shown to the reader as diffs: a problem, then fixed by a setting.** Claude Code
displays every file edit with its added and removed lines. Claude does not choose this,
and `CLAUDE.md` cannot turn it off. A follow-up on 2026-11-24 added `"viewMode": "focus"`
to the test project's settings. With the fullscreen renderer, which the owner's session
already used, an edit then showed as one line, "Edited 1 file +3 -2", with no changed
lines, and no separate diff panel opened. The classic renderer was not tried.

## Follow-up: setting up vibe-kit by asking Claude, 2026-11-24

The brief's open question 2 asks how vibe-kit reaches a reader's project. The candidate:
the reader pastes one sentence into Claude Code, and Claude copies `kit/`'s three files
from GitHub. A plugin was ruled out first: Claude Code's documentation, read through a
summarising fetch, lists no way for a plugin to supply `CLAUDE.md`, permission rules or
settings such as `viewMode`.

The test folder, `~/code/vibe-kit-test2`, held only `.claude/settings.local.json` with the
exclusion of the owner's global instructions, and was not a git repository. The owner
pasted a sentence naming the three raw GitHub URLs at commit `2553ea9`, asking for exact
copies, a question before replacing any file, and `git init` if needed.

**It works.** The three files arrived byte-identical to `kit/`, checked with `cmp`, and the
local settings file was left alone. The folder became a git repository with no commits.

**Asking before replacing works.** The sentence was first pasted by mistake into the older
test session. There Claude found `PROGRESS.md` already present, compared it with GitHub's
copy, described the difference, and asked before replacing it.

**The wording needs two fixes.** Claude used git terms during setup ("a first commit
(git's word for saving a snapshot)"), because the kit's `CLAUDE.md` is not loaded while it
is being installed. And it did not tell the reader to restart, which the kit's opening
needs.

The new repository's branch was named `master`, git's default on this machine. The kit
does not depend on the name.

## Follow-up: the revised sentence, a restart and the first opening, 2026-11-24

The sentence gained "Talk to me in plain words, without git terms. When it is done, tell
me it is ready and that I should close Claude Code and start it again here." It was run in
a fresh folder, `~/code/vibe-kit-test3`, set up like the last one.

**Setup worked, in plain words.** The three files arrived byte-identical to `kit/`. Claude
said the folder "is also set up now to keep saved versions of your work", with no git
terms, and told the owner to restart.

**On restart, Claude Code asked whether to trust the folder**, warning: "This folder
configures hooks that can run commands without asking, declared in .claude/settings.json".
A reader who is not expecting it may answer "No, exit", and the kit would not load. So the
sentence now also asks Claude to say this question is coming, why, and to answer yes. That
addition was tested in `~/code/vibe-kit-test4` the same day: Claude warned that the
question would come, explained it, and said to answer yes.

**The opening worked.** After trusting the folder, the owner typed "hi". Claude said
"There's no project here yet, so we're starting fresh," asked what they would like to
build, and gave two plain examples. It did not mention that the kit's files were not yet
saved.

The sentence as it now stands:

> to CLAUDE.md, https://raw.githubusercontent.com/fbonds/vibe-kit/main/kit/.claude/settings.json

## Follow-up: the renderer, 2026-11-25

Focus view had been tested only on the owner's own choice of the fullscreen renderer. In
`~/code/vibe-kit-test4`, on Claude Code 2.1.332, the local settings were given
`"tui": "classic"`, which Claude Code rejected: "tui: Invalid value. Expected one of:
"default", "fullscreen"". With `"tui": "default"`, `/tui` reported the classic renderer,
and an edit showed in full, with line numbers and the added lines, despite
`"viewMode": "focus"`. So on the default renderer the reader sees diffs.

`"tui": "fullscreen"` was then put in the test folder's project settings, with no `tui` in
its local settings. There was no settings error, and `/tui` reported fullscreen. That the
project setting overrides a user on the default renderer was not tested, because the
owner's own settings also choose fullscreen. It rests on Claude Code's documented order,
project settings over user settings.

## Not tested

The `-f` push form, `git reset --hard`, `git clean`, the staging denies, and the `.env`
read denies. Whether user-level settings other than `CLAUDE.md` shape replies. A reader who
is not the owner.

## Lessons

- A session record does not show every permission prompt. Ask what the screen showed.
- A test run by the kit's author carries the author's own instructions. A clean test needs
  a session without them.
